## How to read the table

- One row per bullet and sub-bullet of the six sections, in PARITY.md's order, nothing merged. A bullet that is only a label ("What the user can do:", "Files:", "REST endpoints") is a row too. Its status is the worst of its children: FAIL over NEEDS-CAPTURE over PASS.
- A "Files" row passes when every file it names has a Markie RS counterpart doing the same job, with tests. How that job looks on screen is judged in the user-facing rows.
- A user-facing row with a screen nobody has compared side by side with Electron is NEEDS-CAPTURE, even when its behaviour and wording pass. The screen was locked for most of this audit (`IOConsoleLocked = Yes`). It unlocked near the end, long enough for one side-by-side, of the new Servers section (21.1.4). Earlier captures are cited where they exist. Signed-in states cannot be paired with Electron on this Mac, because the packaged Electron app refuses a server on localhost.
- Evidence uses `E:` for the Electron source (paths under `src/` or `electron/` of the reference checkout), `RS:` for Markie RS (paths under `rust/crates/`), and `T:` for tests. "e2e" is `crates/markie-cloud/scripts/local-server.sh` against this repo's `server/` on localhost with console mail; "live" is `crates/markie-editor/interop/run-live.sh` (Markie RS and a TipTap peer running the web app's own code, in one room on the same local server).
- Wording was checked mechanically: every user-facing string literal in the Electron components named below was searched for in Markie RS (the script is in the evidence folder). Strings still missing are named in the rows.
