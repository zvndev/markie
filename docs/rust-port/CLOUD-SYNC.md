# Markie RS cloud sync parity

Reference: Markie Electron 0.9.7 and the Electron/server sources. Scope: PARITY.md sections 10 and 30. This is a side build, not a release or a claim of full parity.

## 10. File sync, assets and links

| Inventory item | Status | Evidence or remaining difference |
|---|---|---|
| Turn sync on or off per file | Matches the snapshot operations | Opt-in create, pause, resume and confirmed remote removal. The Registry persists origin, principal, id, base version, hash, last sync time, role, state and media/link results. The first id is persisted before upload and reused after failure. Covered by `cloud_records_survive_reopen_and_keep_recents`, `cloud_sync_assets_links_and_office_bytes` and sync unit tests. |
| Push, retry, pull and remote content | Differs | The desktop queues pushes after Save and autosave, exposes Back up now and checks for updates. Pull will not replace changed disk bytes or a dirty buffer. Pull is offered through Review cloud copy, not the same row menus as Electron. The localhost test covers versions and remote content; the GPUI path was not walkthrough-tested. |
| Keep both, take cloud, overwrite | Differs | All three choices are wired. Keep both writes the local version under an exclusive numbered name, then takes the remote copy. Overwrite asks for confirmation and rechecks the server version. Comparison is bounded side-by-side text, not the Electron line diff. Sync unit tests cover keep-both naming/content and the localhost test covers conflict, take cloud and overwrite. |
| Background reconcile | Differs | A per-origin cursor retries pending writes and media/link changes on a bounded schedule. For an established row, a complete listing is required; a delisted, behind or viewer row is skipped. Version-zero creates reuse the reserved id and can recover an acknowledged snapshot when the listing has the expected hash. Cadence, concurrency and retry presentation differ from Electron. Workspace and HTTP tests cover underlying transitions and guards, not the timer journey. |
| Open shared documents and land owned arrivals | Matches the side-build path policy | Owned arrivals are landed automatically. Shared documents land on explicit open. Both use `~/Documents/Markie RS/Cloud`, or a directory under the scratch data root; they never use Electron's cloud folder. Collision and symlink checks are covered by the two `cloud_landing_*` tests. An owned document whose local copy was removed is not automatically landed again. |
| Assets travel | Differs | Extracts image and HTML media refs, checks local grants and exposure, batches missing hashes, uploads under SHA-256 and links against the acknowledged version. The cache verifies MIME, ETag and downloaded bytes and reauthorizes before returning a path. Native View uses remote image fallbacks without rewriting Markdown. Electron's cache quota/eviction, offline behavior, exact grant set, full audio/video playback and media detail UI are not matched. Tests cover extraction, encoded escapes, symlinks, nested references and HTTP 304. |
| Document links travel | Differs | Markdown/HTML document references link only to registered targets from the same account and origin. The app fetches readable pointers and rechecks the source and target before opening a cloud link. Native anchor restoration and Electron's exact muted-link behavior are not implemented. Unit and localhost tests cover parsing, resolution and the PUT/GET round trip. |
| Multiple servers; origin pinning and token per server | Matches the client boundary | A bound request cannot take another account's token. The Cloud page selects among authenticated trusted origins. Account and Servers settings are the sign-in lane; this branch does not implement the account sheet. Mock tests cover rotation, cross-origin isolation, removal and account replacement. |
| Cloud page and Library badges | Matches in structure | Rebuilt as Electron's cloud workspace: area picker, search with type and order menus, band, source chips with counts, share requests, one row list with source and member-count badges, and snapshot cards (INTEGRATION-CLOUD.md). No signed-in screen evidence yet. |
| Sessions, servers and sync IPC | Differs by architecture | No Electron IPC in Markie RS. Session and server operations use `TokenStore`, `ServerStore`, and the trusted HTTP client. Workspace functions handle on/off, push/retry, check-updates, remote content, resolution, pull, open-shared, media reconcile and document-link open. The registry holds role for the bound principal. |
| `GET /api/docs`, `GET/PUT/DELETE /api/docs/:id` | Matches the existing server contract | Client UUID and base version, SHA-256 text hash, optional area on create, 409 handling. Localhost proof covers GET/PUT and versions; sync unit and mock tests cover DELETE semantics and malformed or stale responses. |
| `GET/PUT /api/docs/:id/links` | Matches the REST contract | Requests use versioned link pairs. Inaccessible target ids are not returned to the editor. Localhost round trip passed. |
| `PUT /api/assets/:sha256`, `POST /api/docs/:id/assets/missing`, `PUT /api/docs/:id/assets`, `GET /api/docs/:id/assets/file?ref=` | Matches the exercised REST contract | Raw typed bytes, missing hashes, versioned references, authorized conditional GET with an intact ETag. Localhost asset round trip passed. |
| `GET /api/server-info` | Matches | Uses the existing probe and confirmation API. The localhost run probes and adds the scratch server before signing in. |

## 30. Byte snapshots

| Inventory item | Status | Evidence or remaining difference |
|---|---|---|
| Upload or replace an office snapshot | Matches the byte protocol; differs in UI | Explicit Create a cloud copy and Save this snapshot to cloud. Local Save never publishes. Uses schema version 2, canonical base64, SHA-256, a 16 MiB cap and a version-matched acknowledgment. A stale update preserves local bytes. RTF round trip and stale version rejection passed against localhost. |
| Cloud document list and area picker | Differs | The Cloud workspace combines text rows and a snapshot list. Scope and upload selection use server areas when available; snapshot placement has explicit buttons. The legacy one-account test server has areas disabled, so the area UI and placement were not exercised there. |
| Open/edit/download cloud office document | Differs | Downloads open as a distinct local file in Markie RS and can be explicitly published back. Electron also edits a cloud snapshot inline without creating a local recovery copy. That inline editor, edited-copy export affordance and exact view-only treatment are not built. Localhost verifies byte-exact download, native file-format support is covered by workspace tests. |
| Manage snapshot members | Differs | Owner UI lists current and pending members, invites by verified email and revokes access. The localhost proof exercises the list with one allowed simulator identity, not a second-account invite and revoke journey. |
| Manage snapshot download links | Differs | Creates a 24-hour link, copies it and revokes the link created in the current dialog. Listing links is supported in the client; management of links from previous sessions is not built in the dialog. Localhost verifies public byte download and refusal after revocation. |
| `/api/document-platform/documents[/:id]` and `/history[/:version]` | Matches the exercised REST contract | List, create, get, replace and history reads through the byte client. Versioned history bytes were verified. No native history browser or snapshot-delete affordance was added. |
| `/members[/:userId]`, `/links[/:linkId]`, and `/api/document-platform/links/:token/download` | Matches the implemented routes | GET/POST/DELETE member and link methods, token download URL and revocation. Localhost verifies member list, create/list/revoke link and anonymous download. Invite/revoke UI remains unverified. |

## Verification and boundaries

- `.autoloop/runs/cloud-sync/local-server-final.log`: real server using an isolated SQLite database, filesystem asset store, console mail and only `success@simulator.amazonses.com`.
- `.autoloop/runs/cloud-sync/final-workspace.log`: `cargo test --workspace` from `rust/` with the pinned toolchain. The opt-in Keychain test stays ignored; localhost integration is run separately above.
- No desktop app was launched or captured. No production authentication or writes, installed Markie profile, real documents, Keychain, or agent configuration were used. Markie RS no longer auto-imports or manually reads the installed Electron profile from this workspace.
- Integration seams outside the new cloud workspace files: lifecycle and saves in `workspace.rs`, the Cloud rail/list and Share routing in `rail.rs` and `chrome.rs`, and lightweight editor resource hooks in `workspace/rich.rs` and `markie-editor`. The sign-in sheet and this workspace now share one token store (`account::shared_tokens`), memory in scratch runs and the Keychain otherwise (INTEGRATION-CLOUD.md).
