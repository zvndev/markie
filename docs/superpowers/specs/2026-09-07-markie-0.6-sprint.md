## Where we start (measured 2026-09-07)

Installed app (arm64): **287 MB**. Of that, the Electron framework is 262 MB (the binary is 170 MB, and ~50 MB is Chromium locale packs Markie never uses). The renderer is 7.1 MB. `app.asar` is 9.5 MB and `app.asar.unpacked` is 15 MB, of which 9.8 MB is sqlite3 C source that ships for no reason.

Correction to what I said earlier: Markie already ships per-architecture builds, not a universal binary. Dropping Next will not shrink the app. The renderer is 3% of it.

Running: **542 to 690 MB RSS across 5 processes** (main 207 to 269 MB, renderer ~200 to 250 MB, GPU and utility helpers ~150 MB). The main process number is suspiciously high for what it does and gets a look in section A.

The 4.4 MB freeze, traced: opening a file runs at least three full TipTap parses of the whole text (`setContent` in the pane, the round-trip probe, and `preserveBlocks`) plus two per-block sweeps over roughly 30,000 blocks inside `requestIdleCallback`s that never check their deadline. The block memo holds 4,000 entries, so a 30k-block file thrashes it. The verdict cache tops out at 4 MB, so this file is evicted the moment it is cached and the probe re-runs on every reopen. There is no size check anywhere on the open path. Scrolling keeps working because the compositor thread is fine; the JS thread is simply gone for minutes.

## Decisions I have made (override any of these)

1. **Large-file thresholds.** At or above **1 MB** a document opens in source view only (CodeMirror is virtualized and handles this fine); the rich pane, round-trip probe, warm-up sweeps and crash journal are all skipped. At or above **100 MB** Markie refuses to open the file and says so. Both are single constants.
2. **Cloud absorbs Shared.** The rail keeps four panels: Library, Browse, Cloud, Skills. The current "Shared" icon becomes "Cloud" and gains the synced and cloud-only sections. The Library panel becomes "On this device" plus Projects; the "In your cloud" and "Shared with me" groups at its bottom go away.
3. **Skills sources.** Defaults: `anthropics/skills`, `obra/superpowers`, `openai/skills`, plus skills.sh search (it has an undocumented JSON search endpoint with install counts; the Vercel CLI repo itself hosts no skills). Any `owner/repo` can be added. Installs are **copies**, never symlinks (symlinks need Developer Mode on Windows; Vercel's CLI falls back to copy too). Markie writes the same lock file the Vercel CLI uses so the two coexist.
4. **Version 0.6.0.** Four user-visible features and a build-system swap is a minor bump, not a patch.
5. **Browse dates** are relative ("2h ago", "Mar 3") with the full date on hover, sortable by name or updated.

## A. Baseline (first, half a day)

A script, `scripts/perf-baseline.mjs`, that launches the packaged app with the e2e consent flag and records: cold launch to first paint (CDP `Page.loadEventFired` plus `performance.timing`), RSS per process after 5 s idle and again with a 200 KB document open, the main process `process.memoryUsage()` (new debug IPC, e2e-only), and time-to-responsive after opening a generated 4.4 MB file (renderer answers a trivial `Runtime.evaluate` within 200 ms, sampled every second for 10 s). Output is JSON plus a one-line summary, committed to `docs/perf/2026-09-07-baseline.json`. The same script runs at the end of the sprint; both numbers go in the changelog.

While in there: a heap snapshot of the main process to explain the 207 to 269 MB. Likely suspects are the markdown index cache and the `md_meta` join. If the fix is under an hour it lands in C; otherwise it is written up as a follow-up.

**Measured (sprint/baseline, 7c7f044; packaged 0.5.4, three runs, medians).** Launch 647 ms from spawn to the load event (run 1 was a true cold launch at 2.5 s), first paint at 92 ms. RSS idle 526 MB: main 177 MB, renderer 195 MB, GPU 88 MB. The main process's JS heap is 7.7 MB used (16.7 MB reserved, 7.9 MB external), so the 177 MB is Electron's own footprint (the framework binary and Chromium's mappings), not Markie's caches. The heap-snapshot question above is closed with nothing to fix, and C carries no main-process memory item. The renderer is the story: opening the 200 KB fixture takes it from 195 MB to 415 MB. The 4.4 MB fixture (33,730 top-level blocks): the editor state holds the document after 1.6 s; the renderer then answers a trivial evaluate in 0 of 20 sampled seconds and no run answered one within the 20 s window; the DOM settles at 57 s (54 to 61 s across runs); switching to another file after that takes 0.4 s. So the freeze is roughly 1.6 s of parsing followed by roughly a minute of ProseMirror building DOM for every block, which is exactly what the 1 MB source-only tier in D removes. D's gate gains one check: landing time for a fixture just under 1 MB, which decides whether that threshold holds or drops.

**Done** (7c7f044): the script runs green against the 0.5.4 build, `docs/perf/2026-09-07-baseline.json` is committed, and `docs/perf/README.md` explains the columns. Rerun at the end of the sprint with the same fixtures.

## B. Vite replaces Next.js (serial, everything else builds on it)

The survey found almost no coupling: one type-only `import type { Metadata } from "next"`, one flat route, no server components, a Tailwind v4 config that is already CSS-first, and a vitest config that is already pure Vite with a hand-rolled `@` alias. Zero tests mock Next.

**Design**
- `index.html` at the repo root (Vite convention) carrying `<html lang="en" class="dark">`, `<body class="antialiased">`, `<title>Markie</title>` and `<div id="root">`. `src/main.tsx` imports `globals.css`, `print.css`, wraps `App` in the existing `ErrorBoundary global` with `CrashProbe`, and mounts. `src/app/page.tsx` stays where it is (fifteen `page.*.test.tsx` files import it) and simply exports `App`.
- `vite.config.ts`: `@vitejs/plugin-react`, `@tailwindcss/vite`, `resolve.alias["@"] = src`, `base: "./"`, `build.outDir: "out"`, `build.emptyOutDir: true`, `build.sourcemap: false`, `build.target: "chrome140"`, `server.port: 3000, strictPort: true`. Keeping `out/` means `release-preflight`'s `out/**` assertion, the CI 12 MB bundle budget, the Windows smoke path filter and `main.js`'s `../out` all keep working untouched.
- `electron/main.js`: the `app://` handler keeps its traversal guard and `buildAppCsp(path.join(__dirname, "../out"))` line verbatim (preflight asserts the literal). The two Next-shaped fallbacks (append `.html`, serve directory `index.html`) collapse into one SPA fallback. Add `codeCache: true` to the `app` scheme privileges so V8 caches bytecode for app:// scripts (this alone is a measurable launch win).
- CSP: Vite emits external module scripts, so `electron/csp.js` will hash zero inline scripts. That is fine; `script-src 'self'` covers same-origin modules. The packaged smoke proves it.
- ESLint: `eslint.config.mjs` is 100% `eslint-config-next` and is replaced with `@eslint/js` + `typescript-eslint` + `eslint-plugin-react-hooks` (rules of hooks, exhaustive deps). The three `@next/next/no-img-element` disable comments go.
- The 41 `"use client"` directives are removed (Rollup warns on each otherwise). `tsconfig.json` drops the Next plugin and `.next` includes, adds `vite/client` types. `next-env.d.ts` and `next.config.ts` are deleted. `public/` loses the five unused scaffold SVGs; `icon.icns` moves to `build/` so Vite stops copying 953 KB into `out/`.
- Scripts: `dev: vite`, `build: tsc --noEmit -p tsconfig.json && vite build` (Next type-checked on build; CI relies on that), `electron:dev` unchanged.
- The 18 e2e scripts that spawn `next dev --turbopack --port N` get one shared helper, `scripts/lib/renderer-dev.mjs` exporting `startRendererDev({ port })` that spawns `vite --port N --strictPort --clearScreen false`, resolves when the URL answers, and returns `{ url, stop }`. Every `.next/dev/lock` cleanup hack in those scripts is deleted with it.
- Dependencies: remove `next`, `eslint-config-next`; add `vite` (explicit), `@vitejs/plugin-react`, `@tailwindcss/vite`, the three ESLint packages. `node_modules` loses ~520 MB.

**Gate:** `typecheck`, `lint`, full vitest (1872 today), `npm run build` yields `out/index.html`, `MARKIE_ALLOW_E2E=1` real-window checks (`sync:check`, `ui:check`, `onboarding:check`, `find:check`, `pdf:check`), a local `electron:build:mac` + `electron:smoke:mac:launch` proving the packaged app loads the Vite output over `app://` with the CSP in place, then Codex review.

## C. Electron tax

**Disk (Opus)**
- `electronLanguages: ["en"]` in `electron-builder.config.cjs` for mac and win. Strips ~50 MB of `.lproj` locale packs. Cost: the handful of Chromium-owned strings (context menu "Look Up", spellcheck labels) show in English for non-English systems. Markie is English-only today, so this is acceptable; noted in the changelog.
- `files` negations for build-time-only native module contents: `!node_modules/better-sqlite3/deps/**`, `!node_modules/better-sqlite3/src/**`, `!node_modules/node-pty/third_party/**`, `!node_modules/node-pty/deps/**`. The `.node` binaries live in `build/Release` and stay. About 12 MB.
- `icon.icns` out of `public/` and source maps off (both land in B).
- Expected: 287 MB installed → roughly 225 MB; DMG 118 MB → roughly 95 MB. Measured, not promised.

**Launch and memory**
- `codeCache: true` on the app scheme (lands in B).
- Lazy-load the export pipeline: `src/lib/markdown-html.ts` pulls unified, remark, rehype-katex, rehype-highlight, KaTeX and highlight.js into the launch path via a top-level import in `page.tsx`, and it is only used for HTML, print and PDF export. Becomes a dynamic `import()` at the export call sites. (Opus)
- Lazy-load CodeMirror: `Editor` mounts only in edit and split mode, yet `page.tsx` imports it statically along with `@codemirror/commands` for undo and redo. `React.lazy` with a Suspense fallback, undo and redo exposed through the editor's imperative handle. (Opus)
- Lazy-load collaboration: `yjs`, `y-websocket` and the two collaboration extensions load on every launch for a feature only active on a shared document. `rich-view.tsx` already keys the collaborative instance separately, so that instance awaits a `loadCollab()` dynamic import before creating its editor. This is delicate (extensions must exist at editor creation) and is Fable's.
- KaTeX CSS stays static: the fonts are `@font-face` and only download when a glyph needs them.

**Gate:** baseline script before and after, install size and DMG size recorded, packaged smoke on mac, `registry` and `node-pty` still load in the packaged app (the sqlite pruning is the risk), Codex review with a performance emphasis prompt.

## D. Large documents

**Tiering, decided in main before the read** (Fable)
- `electron/main.js` `readFilePayload` stats the file first. `size >= MAX_DOC_BYTES` (100,000,000) returns `{ tooLarge: true, size, name, path }` and the renderer shows: "Markie opens markdown files up to 100 MB. This one is 143 MB." Applies to every entry point that reaches `open-file-path`: rows, drag and drop, `open -a Markie`, the CLI and the MCP `markie_open_in_markie` tool.
- `size >= LARGE_DOC_BYTES` (1,000,000) returns the content with `large: true`. The renderer forces source mode, disables the Preview and Split mode buttons with "Too large for rich view", skips the round-trip probe, the warm-up sweep, the crash journal and the content payload of `registryTrack` (main hashes by path instead). Saving and cloud sync work normally, with one IPC per save. A quiet strip reads: "Large document (4.4 MB). Opened in source view; rich editing is off for files over 1 MB."
- Find in source mode already targets CodeMirror; verified as part of the check.

**Below the threshold, stop the hitching too**
- The warm-up loop in `rich-view.tsx` honors `deadline.timeRemaining()`, works in chunks, reschedules itself, and aborts on a document generation change. (Fable)
- The round-trip probe becomes cooperative: it processes top-level blocks in idle slices and yields between them, cancellable when the document changes. Verdict semantics are unchanged; the UI stays responsive during "Preparing". (Fable)
- `restoreHoldAsides` is one regex per hold over the whole text, quadratic; becomes a single pass with a token map. (Opus)
- The find bar re-runs the search on every serialize and walks the ProseMirror doc four times per query; index once per revision, debounce the query 100 ms. (Opus)
- The crash journal posts the full content 250 ms after every change; above 256 KB it throttles to 2 s. (Opus)
- The block memo cap moves from 4,000 entries to a byte budget. (Opus)

**Tests**
- Unit: main returns `tooLarge` above the cap (stat stubbed, no real 100 MB file); page opens a 1 MB document in source mode with the probe never called and `registryTrack` called without content; the warm-up loop processes a bounded number of blocks when the fake deadline has 1 ms left.
- Real window: `scripts/large-doc-check.mjs` generates a 4.4 MB file, opens it, asserts the renderer answers within 200 ms every second for 10 s, that switching to another file completes under 1 s, and that a file over the cap is refused with the message.

## F. Browse redesign (Opus)

- Remove the "All files" tab and the mode toggle. Keep starred-only, full-path toggle, rescan and the filter. `FLAT_CAP` goes.
- **Initial state:** with no remembered state, open every root and follow each single-child chain down to the first folder with two or more entries (folders or files), and open that folder so its contents show. Manual toggles are remembered in `markie.browse.open.v1`.
- **Nesting:** replace `paddingLeft = 8 + depth * 12` with a guide line. Each child list is a container with a 1 px left border in the existing `--border` token (kept quiet, per the earlier border decision), `margin-left` 10 px, `padding-left` 8 px. Rows lose most of their indent but the line keeps depth obvious.
- **Updated column:** right-aligned relative date from `mtimeMs` in muted tabular figures, full date in the tooltip. Sort control "Name / Updated", remembered in `markie.browse.sort.v1`. Sorting by Updated orders files by `mtimeMs` and folders by the newest file beneath them (`buildFolderTree` gains `latestMtimeMs`).
- Folder rows keep their count; the `data-markie-folder-node` attributes stay for the e2e checks.

**Tests:** `folder-tree.test.ts` for the initial-open rule and `latestMtimeMs`; `browse-view.test.tsx` for the removed tab, the guide-line structure, the date cell and both sort orders; `ui:check` screenshot review through Codex image analysis.

## G. Skills: Installed and Discover

Today the Skills panel is a read-only browser over the markdown index for `~/.claude/skills` and `~/.codex`, grouped by tool then by kind, with no skills-specific IPC at all.

**Installed tab** (Opus)
- Grouped by tool: Claude, Codex, Cursor, Gemini, Universal (`~/.agents/skills`). The index allowlist grows by `~/.agents/skills`, `~/.cursor/skills`, `~/.gemini/skills`.
- Within each tool, Skills come first, one row per skill folder with the description from its SKILL.md frontmatter and a badge when Markie installed it ("from anthropics/skills", "update available"). Instructions, Commands, Subagents and Memory follow, collapsed by default.
- Actions: open SKILL.md, reveal in Finder or Explorer, remove (only for skills Markie installed, with confirmation).

**Discover tab** (Opus for the modules, Fable for install safety)
- Source chips for the three defaults and any added `owner/repo`. A search box filters the loaded catalogs; at two or more characters it also queries `https://skills.sh/api/search?q=…&limit=20`, shown as "From skills.sh" with install counts, and choosing one loads that repository into the catalog. The endpoint is undocumented, so it degrades to local search silently.
- Row: name, two-line description, source, license badge (four of Anthropic's skills are proprietary and the badge says so), installs when known.
- Detail: SKILL.md rendered in Markie's own read-only preview, the file list with sizes (scripts, references, assets), the license, and **Add to…** with checkboxes for Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Cursor (`~/.cursor/skills`), Gemini (`~/.gemini/skills`), Universal (`~/.agents/skills`), and Project (pick a workspace root, installs to `<root>/.claude/skills`). Claude Code is checked by default; the last choice is remembered.
- **Fetching** (`electron/skill-registry.js`): one request per repository to `https://codeload.github.com/{owner}/{repo}/tar.gz/refs/heads/{branch}` (main, then master), streamed through `zlib` and a ~80-line ustar reader, so no new runtime dependency (release preflight forbids any). Skill folders are recognized the way the Vercel CLI does it: a directory with `SKILL.md` whose frontmatter has string `name` and `description`, inside `skills/`, `skills/.curated/`, `.claude/skills/`, `.agents/skills/`, `.codex/skills/` or the root, three levels deep. Frontmatter is parsed by a small YAML-subset reader that handles quoted strings and `|`, `|-`, `>` block scalars (Anthropic's descriptions use them). Extracted into `userData/skill-cache/{owner}/{repo}/{sha}/`. Update detection is one `GET /repos/{o}/{r}/commits/{branch}` per repository per check with a User-Agent, cached 24 h, and the cache is used when rate-limited ("checked 40 min ago"). Tarball size is capped at 50 MB; entries with `..`, absolute paths or symlinks are skipped.
- **Installing:** name must match `^[a-z0-9]+(-[a-z0-9]+)*$` and be at most 64 characters, and the resolved path must stay inside the target directory. Files are copied with the executable bit preserved for `scripts/`. An existing folder is never overwritten unless Markie installed it from the same source, in which case the button reads Update. Nothing is ever executed. A `skill_installs` registry table (`source, skill, target_path, folder_hash, installed_at`) drives the Installed badges, and an entry is written to `~/.agents/.skill-lock.json` in the Vercel v3 shape so `npx skills` and Markie agree.
- IPC: `skills-catalog-list`, `skills-catalog-refresh`, `skills-catalog-add-source`, `skills-search`, `skills-install`, `skills-remove`, `skills-installed`.

**Tests:** ustar reader against a tarball built in the test; frontmatter parser on the block-scalar cases; discovery across the container layouts including `skills/.curated`; install path safety (rejects `..`, uppercase, overwrite of a foreign folder); lock file merge; UI tests for both tabs and the Add flow with the mock bridge. Real network: `scripts/skills-check.mjs` fetches `anthropics/skills`, installs one skill into a temp HOME, asserts the files, the registry row and the lock entry.
